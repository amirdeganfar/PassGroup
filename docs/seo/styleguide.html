Article component style guide — Pass Group

Every widget the article-writer can use, rendered with the real site stylesheet (styles/pass-article.css). Same classes live in WP → Customize → Additional CSS. Rule: 3–5 components per article, picked to fit the content — never the whole menu.

How to read this: the grey box under each label tells you when to use that widget; the rendered block below it shows how it looks on the live site.
Key takeaways — pass-tldr
The "short version" for scanners, near the top. 3–4 bullets. Use on pillar pages + long articles. Snippet bait for Google.
Short version
  • A simple app in Australia typically costs $5,000–$20,000 — not the $30k–$300k most guides quote.
  • Four things set the price: screens, integrations, who builds it, and polish.
  • You pay once to build, then roughly 10–20% of the build cost per year to run it.
Single key takeaway — pass-keytakeaway
One highlighted sentence — the one thing to remember from the section. Alternative to the tldr box when you only have one takeaway. Tone-aware.

Before you compare quotes, write down the three screens your app truly needs on day one. Everything else is version two.

Smaller version one = faster launch = money left to improve it.
Drop-cap opener — pass-lead
Editorial opener. Use once, on the first paragraph only, for story-led articles.

The first quote came back at $180,000. The founder had $15,000, one idea, and a spreadsheet of forty-two features. Six months later the app was live — with eight of them.

Coach's story — pass-story (tone: gold)
A first-hand experience moment (E-E-A-T). One per article, in the author's voice. Label text can change to fit the story.
A pattern we see weekly

Founders rarely blow their budget on features — they blow it on rebuilding the same screen three times because nobody wrote the scope down. One afternoon with a pen saves a month of invoices.

Callout / Tip / Warning — pass-callout · pass-tip · pass-warning
The single most important point of a section (callout), a helpful aside (tip), or a safety/"don't do this" note (warning). Max 2–3 per page, and only where they mean something.
The build fee buys the code once — the maintenance fee keeps it working on every new phone model, year after year.
Ask for the quote split by phase. Discovery, design, build, launch — each should be a separate number.
Never start build before the scope document is signed. "We'll figure it out as we go" is how budgets double.

Steps — pass-steps
Numbered step cards for any how-to. Each step = small heading + 1–2 sentences.

  1. Write the one-paragraph brief

    Who uses it, what it does, what it must not do. If it takes more than five sentences, it's a spec, not a brief.

  2. List the screens

    Every screen adds cost. Ten is a normal first app.

  3. Get quotes split by phase

    Compare like with like — the same scope, priced three ways.

Timeline — pass-timeline
Vertical week/phase dots — for "what happens when" (discovery → design → build → launch). Alternative to a plan table.
  • Weeks 1–2 — discovery workshop, fixed scope, fixed quote.
  • Weeks 3–5 — designs you click through before a line of code exists.
  • Weeks 6–10 — build, with a demo call every fortnight.
  • Week 11 — App Store and Google Play submission.
Do / Don't — pass-dodont
Two-column green/coral list — for mistakes and corrections (myth-buster articles).

Do

  • Fix the scope before the price
  • Launch small, improve monthly
  • Keep a 15% contingency

Don't

  • Pay the full build upfront
  • Copy a competitor app feature-for-feature
  • Start without a signed IP clause
Comparison cards — pass-comparison
"This vs that" two-column cards — when the reader must pick between two options (native vs cross-platform, agency vs freelancer).

Local agency

  • Same timezone, same language
  • Higher hourly rate ($120–200)
  • Face-to-face workshops

Offshore team

  • Lower hourly rate ($30–80)
  • More project management from you
  • Check IP and contract law carefully
Checklist — pass-checklist · Icon list — pass-iconlist
Light ticked list (checklist) vs the heavier designed list with dividers (iconlist — also used for the pillar's hub/related links section).
  • Idea validated with five real potential users
  • Scope document signed
  • 15% budget buffer set aside
  • Fixed price for fixed scope — always.
  • Source-code IP lands with you, not the builder.
  • Any quote that skips discovery entirely.
FAQ accordion — pass-faq
Expandable Q&A — pair with FAQPage schema on pages answering several small questions. (Link each question to its own QA micro-page when one exists.)
Can I update the app myself after launch?

Content like text and images — usually yes, through a simple admin panel. Code changes — no, that's what maintenance covers.

Do I need an ABN to launch an app business in Australia?

To charge for it, practically yes — and the ATO expects the income declared. Your developer doesn't need it; you do.
