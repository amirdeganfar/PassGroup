AI didn't make apps cheap. It made demos nearly free — and that difference is the whole budget. So, how much does it cost to build an app with AI? A working demo can genuinely cost tens of dollars and a weekend: tools like Lovable and Replit start free, with serious plans from about US$20 a month. A production app — one that handles payments, real users and their data — still costs five figures to build properly, AI or not. The myth worth puncturing first: "AI" and "finished product" are not the same purchase.

Those bands are planning guides, hedged on purpose — pricing changes, and scope decides almost everything. What holds steady is the shape: the demo is pocket money, the subscription is a rounding error, and production is a project. The sections below walk each stage and where the money actually moves.

It's worth being precise about what the middle band buys, because this is where budgets drift. The US$20–$100 monthly plans cover building, but "built" is a moving target: each new feature is more credits or effort, each month of iterating is another subscription cycle, and the moment you want custom domains, higher limits or team seats, you move up a tier. That's not a criticism — it's the same pay-for-what-you-use logic as electricity. The budget discipline is simply knowing what "done" looks like before you start paying for it. The demo-to-production gap in plain words

A demo answers one question: does this idea make sense? It can skip the boring, expensive parts — the parts production can't. Authentication (how people log in safely) must resist attackers, not just work for friends. Payments must handle refunds, failures and disputes. Privacy means storing user data responsibly — in Australia, the Notifiable Data Breaches scheme sets real obligations once you hold personal information. And edge cases — the odd, unplanned situations real users create — are where software earns its price.

AI closes some of that gap every month, to be fair. But "mostly right" code that fails on the hundredth user still needs an experienced human to find and fix it. That's the gap, and it's where production money goes.

There's a quieter cost in the gap too: performance under load. An app that works for ten users can crawl for a hundred, and no demo weekend ever tests that. Then there's app-store review — Apple and Google reject incomplete or unstable apps, and a review-savvy team knows the difference between "almost ready" and "approved". None of these show up in a demo, and all of them show up in a launch.

Where AI genuinely saves money in real builds

Do hand AI this

  • Prototypes and clickable demos
  • Boilerplate code — the repetitive scaffolding every app needs
  • First drafts of documentation and tests
  • Translating plain-English specs into something reviewable

Don't bet the app on AI for

  • Payment and money-handling logic
  • Security and privacy architecture
  • Code nobody can read, review or fix
  • Deciding what to build in the first place

Used that way, AI trims real hours off professional builds too — it's part of why focused first versions now cost less than they did a few years ago. The saving is real; it just arrives inside a human-led project, not instead of one.

If you want to see the saving yourself, watch what a professional build actually does with AI: a rough interface finished in a day instead of a week, tests written while the developer reviews them, and documentation that exists because it was nearly free to produce. Hours like those come straight off a quote. Hours spent untangling generated payment code go the other way — which is why the do/don't list above is really a cost list in disguise.
